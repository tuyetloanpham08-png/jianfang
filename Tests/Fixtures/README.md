# 合成回归输入

公开源码默认不包含测试媒体二进制。运行测试前，在仓库根目录执行：

```sh
python3 scripts/generate_fixtures.py
python3 scripts/make_step7_fixtures.py
```

第一个脚本生成 `fixtures/media/` 下的 27 个样例媒体文件，供仓库已有的 JSON/SRT 工程引用，不修改这些文本工程。第二个脚本生成 `Tests/Fixtures/media/` 下的 8 个回归视频。

仅生成媒体时需要 Python 3 和支持 `libx264`、`libx265` 的 FFmpeg。图像和 WAV 使用 Python 标准库生成，JPEG 使用 FFmpeg 编码，不需要 Pillow。App 的运行及 Swift 编译本身不依赖这些工具；首次打包内置演示素材和运行完整测试前需要先生成相应输入。不同 FFmpeg 版本可能产生不同编码字节，验收应以时间、编码、画面和声音语义为准。

两个脚本都会在任何写入前检查所有计划目标。只要其中一个已存在，整个脚本就会拒绝执行；不覆盖、不删除。失败后的未完成文件也会保留。需要重新生成时，可用 `--output-dir` 指定另一个新目录，由开发者核对后自行放到测试引用的位置。

## 回归视频规则

视频仅包含黑白竖带，以及部分视频中的 1 kHz 合成正弦音，不使用摄像素材、对白或用户工程。每帧有十条竖带，第 `b` 条表示源帧号的第 `b` 个二进制位，有限范围亮度值为 16 或 235。除专门验证格式拒绝或时基边界的文件外，视频为 SDR BT.709、8 位 4:2:0、15360 时基；音频为 AAC、48 kHz 双声道。每段约四秒。

| 输入 | 用途 |
| --- | --- |
| `hevc-1440p60.mp4` | 2560×1440、HEVC、60 fps，用于编码、尺寸、帧率拒绝检查。 |
| `hevc-1440p60-compatible-v2.mp4` | 1920×1080、H.264、30 fps；取上述 HEVC 输入的偶数源帧。 |
| `av-audio-short-v2.mp4` | 四秒画面，编码前 3.989 秒的合成音。 |
| `av-audio-long-v2.mp4` | 四秒画面，编码前 4.021 秒的合成音。 |
| `av-audio-long-100ms-v2.mp4` | 四秒画面，编码前 4.1 秒的合成音。 |
| `cfr30-tb1000.mp4` | 30 fps 恒定帧率，在 1/1000 秒时基上舍入时间戳。 |
| `cfr24-tb1000.mp4` | 24 fps 恒定帧率，在 1/1000 秒时基上舍入时间戳。 |
| `vfr-jitter30-v3.mp4` | 标称 30 fps，奇数帧延迟 0.0133 秒，构造真实可变帧率。 |

字幕、旧格式恢复快照和 MP4 box 顺序样本直接在 Swift 测试内由明确的合成数据构造，不依赖历史界面会话、测试过程记录或旧成片。
